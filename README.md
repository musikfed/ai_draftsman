# PEGINELAB AI Draftsman

Лёгкая **универсальная локальная AI-студия**: пользователь создаёт любой проект, собственный граф узлов, пишет промпты, подключает локальную Ollama и генерирует изображения через независимый Python Diffusers worker. **Karate Linux — опциональный шаблон**, не встроенное обязательное ограничение.

## Главный экран: промпты, поиск и пузырьки

В режиме **«Быстрый рисунок»** оригинальные промпты и их русские переводы показаны **в соседних колонках** (положительный и негативный отдельно). Сохранённые переводы берутся из SQLite без повторного обращения к Qwen при просмотре. Последние 8 рисунков на странице можно выбрать, выделить, листать стрелками и горизонтальной прокруткой; **«⌕ Поиск»** открывает все результаты. Во время ожидания вместо черепахи показываются пузырьки разного размера и цвета.

Ранее экспериментальные мультяшные SVG-файлы остаются в репозитории как неиспользуемые исходники. [Историческое описание предыдущей анимации](docs/PROMPT_GALLERY_AND_TURTLE_RU.md).

## Повтор генерации в карточке и единственный GPU-рендер

По кнопке **«Сгенерировать снова»** во вкладке «Результаты» студия **не переключает вкладку**: исходный рисунок временно закрывается плавной анимацией пузырьков, а на его месте виден **этап и процент** нового GPU-задания. После завершения ожидание исчезает, исходник остаётся без изменений, новая версия появляется среди свежих результатов. При ошибке сообщение выводится **непосредственно на карточке**, а не только в нижней части страницы.

**Никакой очереди:** с момента начала запуска все кнопки «Сгенерировать снова» и кнопка «Генерировать» в быстром/графовом режиме блокируются. Другая вкладка браузера узнаёт о занятости через лёгкий `GET /api/jobs/active` (опрос раз в 4 секунды во время видимости страницы). Сам сервер дополнительно возвращает HTTP 409 при конкурентной попытке — `studio.jobs.submit_job` уже проверяет занятость под блокировкой, а неуспешные попытки не создают лишние версии черновиков. Во время рендера отдельные шаги идут последовательно, второй GPU-процесс не запускается. При F5 интерфейс восстанавливает статус из `spec.json` и `state.json`.

Проверка на Huananzhi после `git pull --ff-only`: `uv run --no-sync python -m unittest discover -s tests -v`, затем `bash scripts/run.sh`. Дополнительные фоновые службы не устанавливаются.

## Крупные карточки результатов

Карточки во вкладке **«Результаты»** оформлены по пользовательскому эскизу (ноябрь 2026):

- **Сверху:** широкая кнопка «Сгенерировать снова» и красная «Удалить» с подтверждением; в архиве удаление заблокировано.
- **В центре:** крупный рисунок с пропорциями 4:5, индекс `R-000002` поверх изображения и оценка, если выставлена. Название, черновик и Seed остаются доступны в подсказке и базе — длинные тексты не занимают высоту карточки.
- **Снизу:** «Открыть», «Промпт», «В архив» (для архивной записи — «Вернуть»). Эти кнопки вызывают прежние действия и API.
- По **две карточки в ряд** на широком экране, **одна** на планшете или телефоне. Файлы PNG, структура заданий, каталог SQLite и модели при изменении оформления не затрагиваются.

## Удаление результата

Во вкладке **«Результаты»** у каждой карточки есть красная кнопка **«Удалить»**. После подтверждения удаляются **только выбранный PNG и master PNG**, оценка и индекс результата в SQLite, а также запись варианта в `state.json`. Последний вариант удаляет пустую связь с черновиком, но сам черновик и параметры задания остаются. **Архивные карточки защищены от удаления**. Подробнее: [правила удаления и восстановления при ошибке](docs/DELETE_RESULT_RU.md).

## Интерфейс быстрого рисунка

- **Промпты и переводы:** положительный и негативный промпты — слева, их **сохранённые русские переводы** — справа. Перевод не запускается при каждом просмотре: он читается из SQLite после сохранения версии, Qwen вызывается только для отсутствующего перевода.
- **Последние эскизы:** в одной горизонтальной ленте **8 результатов на странице**. Выбранный эскиз подсвечивается, справа открывается его существующий результат. Листать можно стрелками, мышью, тачпадом или горизонтальной прокруткой; в узком окне лента прокручивается. Кнопка **«⌕ Поиск»** открывает полную вкладку результатов.
- **Ожидание:** черепаха больше не используется, только разноцветные пузырьки разного размера; GIF или тяжелые библиотеки не нужны.

## Обновить уже установленную студию

В терминале действующей Flask-панели нажать Ctrl+C, затем:

```bash
cd /1tbdisk/PegineLab/ai_draftsman
git pull --ff-only
bash scripts/install.sh --gpu   # Flask + отдельное CUDA-окружение, без скачивания моделей
uv run --no-sync python -m unittest discover -s tests -v
bash scripts/run.sh
```

**Что делает установщик:** `bash scripts/install.sh` обновляет только Flask-окружение; `bash scripts/install.sh --gpu` добавляет отдельное CUDA-окружение. При повторном запуске исправное GPU-окружение не переустанавливается. Все окружения, временные файлы загрузок и кэши размещаются под `/1tbdisk/PegineLab/ai_draftsman`. Сами модели SDXL не скачиваются автоматически — это отдельная кнопка в интерфейсе. `bash scripts/run.sh` только запускает уже подготовленную панель, без автоматической установки пакетов.

Без sudo, chown, chmod и без повторной установки существующей Ollama. Для переключения интерфейса желательно обновить страницу браузера с Ctrl+F5. Если `git pull --ff-only` отклоняет незакоммиченные локальные изменения, не применяй `reset --hard` — разбери изменения отдельно.

## Режимы работы и полноэкранная компоновка

Главная страница теперь растягивается на всю доступную ширину браузера; поле графа подстраивается под размер окна и показывает внутреннюю прокрутку только при больших схемах.

**⚡ Быстрый рисунок — без графа:** отдельные поля «Что нарисовать» и negative prompt, выбор Ollama для улучшения текста, генерация через text-to-image или img2img по одному загруженному образцу. Не требует создания проекта и утверждения узла. Промпт сохраняется в SQLite кнопкой «Сохранить черновик» и при запуске генерации.

**◈ Проекты и граф:** существующий редактор с сохранением координат узлов, связей, глобального и узлового промптов, FTS5 и выбранной LLM.

В обоих режимах общая правая панель позволяет выбирать число вариантов, Steps, CFG, seed, силу преобразования, референс и LoRA. **Граф не обязателен для рисунков.**

**Ожидание:** до готовности результатов показываются карточки-скелетоны для 1–3 вариантов, этап загрузки / генерации / сохранения и процент прогресса из файла `state.json`. Пока задача выполняется, браузер проверяет только её статус раз в 4 секунды, пропуская скрытую вкладку; после готовности опрос прекращается. Глобальные показатели CPU/RAM/VRAM/SWAP/зомби/дисков обновляются только по кнопке.

**Перезапуск страницы:** текущий быстрый промпт и общие данные лежат в SQLite, каждая графическая задача сохраняет свой `spec.json`, `state.json`, `worker.log` и картинки в `data/jobs/<job-id>/`. «История генераций» загружается с сервера после F5. Дополнительные детали: [обучение, память, референсы](docs/TRAINING_AND_MEMORY.md).

## Варианты, модели и ожидание

**Варианты свободно:** впиши число **1–48** в поле, либо оставь **«авто»** и напиши в промпте «сделай семь вариантов», «7 изображений» или «5 variants». Парсер распознаёт число только при указании `вариантов/изображений/pictures`. Слова «пять слайдов» не означают пять альтернативных версий одного рисунка — это отдельные кадры истории. Максимум 48 на одно задание; GPU создаёт их **строго последовательно**, не 48 одновременно. На старой RTX 3060 с offload большие серии будут долгими.

**Анимированное ожидание:** вместо черепахи в подводной карточке отображаются полупрозрачные **цветные пузырьки** со случайными размерами, координатами, скоростями, дрейфом и фазами. В одиночной карточке 26 пузырьков, при нескольких параллельных карточках — по 16. Остались лёгкие световые лучи и подписи вариантов. Анимация работает исключительно в браузере, без модели, React и дополнительной нагрузки на GPU worker. **«🌊 Демо ожидания»** показывает пузырьки без отправки задания. Учитывается системная настройка `prefers-reduced-motion`. Опрос активного задания — раз в четыре секунды; мониторинг CPU/RAM/VRAM остаётся по нажатию.

**Два независимых типа моделей:**
- **Ollama / Qwen** — текстовый агент: сценарии, граф, создание/prompts и текстовый RAG; они уже установлены на сервере. Загрузка других LLM через Ollama может потреблять место на системном разделе, заранее проверь расположение `OLLAMA_MODELS`.
- **Diffusers / SDXL** — графическая модель для рисунков. Встроенный каталог совместимых моделей: **Illustrious XL v2.0** (манга, стилизованные иллюстрации) и **Stable Diffusion XL Base 1.0** (общие изображения), обе доступны с Hugging Face по явному нажатию «Скачать выбранную SDXL». Вес модели — обученный checkpoint `.safetensors`, не модель Ollama. Разные несовместимые семейства (Flux, SD1.5 и т.д.) нельзя подсовывать SDXL-пайплайну без отдельной реализации.
- **Собственные LoRA** — дообученные адаптеры для персонажей и стиля, совместимые с выбранной базовой SDXL-моделью. В текущей версии можно выбрать готовую LoRA из `models/loras`, но обучение своих LoRA пока не реализовано.

**Как освобождается VRAM:** на запрос изображения сервер проверяет, что другое GPU-задание не активно, и через Ollama API пытается выгрузить уже загруженные языковые модели (`keep_alive=0`). Затем запускается **один** отдельный PyTorch-процесс, который загружает только выбранный SDXL checkpoint, с `enable_model_cpu_offload()`. Даже если заказано 30 вариантов, SDXL загружается один раз для задания. После окончания процесс уходит и его CUDA-контекст освобождается. При следующем запросе к Qwen Ollama сможет загрузить свою модель снова. Это **не гарантирует** отсутствие VRAM-конфликтов с посторонними процессами, запущенными вне студии.

**Память**: SQLite хранит проекты, связи, промпты, модель LLM и текстовый RAG; `data/jobs/<id>/spec.json`, `state.json` и PNG хранят фактический checkpoint, параметры, историю прогресса/результатов. Локальный браузер хранит только настройки отображения (например, выбранную графическую модель и введённое число вариантов), это не единственный источник памяти. Ни освобождение VRAM, ни закрытие Flask не стирают обучающие веса или документы. Отдельная история генераций доступна после перезагрузки страницы.

Для теста: `uv run python -m unittest discover -s tests -v`. Тесты на GPU-free параметры, каталог SDXL, сетевые маршруты и изоляцию проектов добавлены; **реальный запуск генерации на Huananzhi ещё не подтверждён**.

## Универсальные проекты

В новой главной странице доступно:

1. **+ Новый проект** — произвольное название, тематика, описание цели. Не содержит фиксированных уроков и персонажей.
2. **+ Узел** — типы Scene/Character/Style/Prompt/Reference/Note/Output/Lesson/Slide, редактируемое название, описание, собственные положительные и негативные промпты. Любое количество узлов.
3. **Граф** — перетаскивание узлов мышью с сохранением позиции в SQLite; ручные направленные связи; удаление связей и узлов.
4. **Промпты проекта** — общий визуальный стиль, общий negative prompt и отдельная **системная инструкция для Ollama**. Промпты текущего узла и графовый контекст показываются кнопкой «Итоговый промпт».
5. **LLM: составить промпт** — запрос в установленную Ollama по выбранному узлу. Агент получает настройки проекта, связанный контекст и TXT/MD-знания. Ответ сохраняется как *черновик*; утверждать его должен пользователь.
6. **Загрузка LLM** — через Ollama API только по явному нажатию; доступны установленные модели, отдельно кнопка скачать новую и проверить её статус.
7. **Генерация изображения** — исходные размеры 768×960/896×1120, txt2img или img2img по одному загруженному референсу, 1–3 варианта *одного узла*, Steps/CFG/Seed/strength и опциональная SDXL LoRA.
8. **Контроль результатов** — отдельное GPU-задание, ручная проверка статуса, ссылки на PNG-8 800×1000 и полноцветные master PNG.

### Шаблон Karate Linux

Старые таблицы `slides`, `rag` и `rag_fts` **не удаляются и не изменяются** этой миграцией.

### SQLite

Новые таблицы: `studio_projects`, `studio_nodes`, `studio_edges`, `studio_knowledge` (FTS5). Их создание выполняется автоматически при запуске Flask, без замены существующей базы `data/draftsman.db`. Проекты изолированы; связи между узлами разных проектов запрещены. Для каждого проекта собственная LLM и TXT/MD RAG. Векторный поиск и обучение LoRA ещё в плане.

## Работа с LLM (не путать с графической моделью)

На Huananzhi уже установлены **qwen3:8b, qwen3:4b-instruct, qwen2.5vl:7b, nomic-embed-text** и другие модели. Для сценариев новая загрузка необязательна: выбери существующую в настройках проекта.

«Скачать LLM» вызывает Ollama API `/api/pull` по явному нажатию. **Важно:** файлы Ollama попадут в каталог модели, настроенный у действующей службы Ollama. Его расположение студия не меняет. Если служба хранит модели на `/`, где осталось около 16 ГБ, сначала проверь свободное место и фактический каталог хранения, не скачивай тяжёлые модели вслепую. Загрузку можно проверить вручную кнопкой «Статус загрузки».

**Ollama пишет текст и сценарии, а не рисует изображения** через этот интерфейс. Для графики нужен SDXL checkpoint и локальное GPU-окружение:

```bash
cd /1tbdisk/PegineLab/ai_draftsman
bash scripts/install_gpu.sh
```

И отдельно по желанию кнопка «Скачать Illustrious XL». Эти установки не происходят автоматически после `git pull`.

## Архитектура одного рисунка

Project + Node + связанные предки графа + Positive/Negative prompt → Flask создаёт job → изолированный Python/PyTorch Diffusers worker → 1–3 картинки PNG + PNG-8 → worker завершается и освобождает CUDA-контекст. Веб-страница не проводит вычисления и не опрашивает сервер каждую секунду.

**Две кнопки питания**: «ВЫКЛ студию» закрывает только Flask; «Освободить VRAM» просит Ollama выгрузить загруженные модели, если нет активного задания генерации. Остальные службы не трогает.

## Ограничения текущей версии

- Не гарантируется графическое постоянство персонажей без собственной обученной LoRA и отобранных референсов.
- Пока доступен **один референс** для img2img, не полноценный multi-reference conditioning.
- Проектный RAG пока **текстовый FTS5**. Векторный слой (`nomic-embed-text`/sqlite-vec), отдельная графовая визуальная память и обучение LoRA ещё не реализованы.
- Генерация точного текста внутри облачков, автоматическое создание целых комиксов/ZIP и система контроля художественного качества пока отсутствуют.
- Python/GPU тесты на реальном Huananzhi должны пройти отдельно — наличие кода в GitHub не означает, что inference уже проверен.
- Порт 9898 не имеет аутентификации: только доверенная тестовая локальная сеть.
- Переводы расширенного нового редактора полностью подготовлены на русском/английском, для остальных девяти языков основные пункты локализованы с русским fallback.
