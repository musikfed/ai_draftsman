# AI Draftsman — инструкция по генерации без LoRA и с LoRA

Пошаговое руководство для **локальной** веб-студии на Huananzhi X79, Ubuntu 24.04, NVIDIA RTX 3060 12 ГБ. Интерфейс: **http://192.168.0.100:9898** (только доверенная локальная сеть).

> **Главное:** для обычных рисунков LoRA **не требуется**. SDXL Base 1.0 или Illustrious XL v2.0 — уже обученная графическая модель (checkpoint). LoRA — небольшой *дополнительный* адаптер, изменяющий стиль, персонажа или иной навык. Ollama/Qwen помогает с текстом промпта, но не является графическим движком.

## 0. Запуск, обновление и остановка

Обычный запуск в терминале сервера (без systemd, Docker и фоновой службы):

```bash
cd /1tbdisk/PegineLab/ai_draftsman
bash scripts/run.sh
```

Остановить: **Ctrl+C** в терминале с запущенной студией. Обновить код (только при необходимости, после остановки студии): `git pull --ff-only`, затем `bash scripts/run.sh`. Не запускать повторную установку GPU-окружения при каждом старте. Не выполнять `git reset --hard` для «лечения» конфликтов. Не обновлять код/не перезапускать Flask во время скачивания checkpoint или активной генерации.

По скриншоту от 21.11.2026 обе модели в списке отмечены **«установлена»**: **Stable Diffusion XL Base 1.0** и **Illustrious XL v2.0**. Повторно скачивать их не нужно. Это состояние *показанного сервера*, а не автоматическая проверка любой другой установки.

## 1. Первый рисунок — БЕЗ LoRA (рекомендуемый тест)

1. Открой вкладку **«⚡ Быстрый рисунок — без графа»**. Проект, узел и утверждение не нужны.
2. В левое поле **«Что нарисовать — положительный промпт»** вставь:
   ```text
   A photorealistic cute ginger kitten wearing stylish red glasses, looking at the camera, detailed fluffy fur, soft natural light, cozy background
   ```
3. В **«Чего не должно быть — негативный промпт»**:
   ```text
   blurry, low quality, distorted anatomy, extra legs, extra ears, cartoon, anime, text, watermark
   ```
4. Необязательно: нажми **«ИИ: улучшить промпт»** для редакции через Ollama/Qwen. Для первого GPU-теста лучше пропустить эту операцию. Нажми **«Сохранить черновик»**, если нужно сохранить текст в SQLite.
5. Справа **«Генерация изображения»** установи:

   | Поле интерфейса | Первый тест |
   |---|---|
   | Режим | **По описанию** (txt2img) |
   | Вариантов | **1** (не «авто») |
   | Размер | **768 × 960** |
   | Seed | **0** — случайное начальное значение |
   | Steps | **28** |
   | CFG | **6,5** |
   | Графическая модель SDXL | **Stable Diffusion XL Base 1.0 — установлена** |
   | Изображение-образец | **Без референса** |
   | SDXL LoRA | **Без LoRA** |
   | Сила img2img | Не применяется для режима «По описанию» |

6. Нажми оранжевую кнопку **«Генерировать»**. Первая генерация может дольше готовить pipeline/кэш; загрузка дополнительной конфигурации на первом старте может требовать доступа к Hugging Face, даже если сам checkpoint уже на диске.
7. Появятся этапы, процент выполнения и анимация ожидания. Кнопка **«Проверить результат»** вручную запрашивает статус; в ходе активной задачи интерфейс также опрашивает её статус автоматически. **«🌊 Демо ожидания»** проверяет анимацию и **не запускает GPU-генерацию**.
8. После завершения открой результат. **«История генераций» → «Открыть результат»** позволяет вернуться к сохранённой задаче, в том числе после F5.

**Где результат:** `data/jobs/<job-id>/` — параметры `spec.json`, состояние `state.json`, лог `worker.log`, результаты в подкаталоге `images/`. Для изображения сохраняются полноцветный master PNG и PNG-8 размером 800 × 1000. При seed=0 сервер выбирает случайный seed и записывает фактически использованное значение в задание.

## 2. Генерация С LoRA

### 2.1. Выбрать совместимый адаптер

**LoRA должна соответствовать архитектуре и желательно конкретному checkpoint**, на котором обучалась:

| Выбранная графическая модель | Какую LoRA искать |
|---|---|
| **Stable Diffusion XL Base 1.0** | LoRA для **SDXL 1.0 / SDXL Base**; наиболее предсказуемый старт |
| **Illustrious XL v2.0** | Предпочтительно LoRA, обученную на **Illustrious XL**, желательно близкой версии |
| **SD 1.5 / Flux / другие семейства** | Их LoRA **не являются заменой** LoRA SDXL; не использовать в этом SDXL-пайплайне |
| **Ollama / Qwen** | Языковые адаптеры другой архитектуры; в выпадающий список **SDXL LoRA** не подходят |

Обычная SDXL LoRA иногда технически загрузится с Illustrious XL (оба относятся к SDXL-семейству), **но это не гарантия качества**. Перед скачиванием изучи описание автора: base model, trigger words, рекомендованные коэффициенты, лицензию и условия коммерческого применения. Каталоги для поиска: https://huggingface.co/models и https://civitai.com/models . Для работы уже скачанной LoRA облако Kaggle/Hugging Face **не нужно**.

### 2.2. Положить файл в каталог студии

Текущая реализация **не скачивает LoRA кнопкой**: она показывает локальные файлы `.safetensors` в **ровно одном каталоге**:

```text
/1tbdisk/PegineLab/ai_draftsman/models/loras/
```

Создать каталог, не трогая существующие модели:

```bash
mkdir -p /1tbdisk/PegineLab/ai_draftsman/models/loras
```

Скачать выбранную **совместимую** LoRA на сервер из страницы автора (прямая ссылка на сам `.safetensors`, а не HTML-страницу). Пример шаблона, адрес **заменить на реальный проверенный URL файла**:

```bash
cd /1tbdisk/PegineLab/ai_draftsman/models/loras
curl -fL --retry 3 --output my_sdxl_lora.safetensors 'https://EXAMPLE/actual-file.safetensors'
ls -lh my_sdxl_lora.safetensors
file my_sdxl_lora.safetensors
```

Можно также вручную перенести уже скачанный файл в эту папку; не нужны `sudo`, `chown`, `chmod` для работающего пользовательского каталога. Если файл оказался маленькой HTML-страницей, архивом, неполным или запросил авторизацию — не пытаться использовать его как веса. Имя файла должно быть простым (латинские буквы/цифры/пробел/точка/`_`/`-`) и оканчиваться **`.safetensors`**.

**Опечатка:** `models/lorasas` — **неверный** каталог; студия читает только `models/loras`.

### 2.3. Выбрать LoRA в интерфейсе и нарисовать

1. Убедись, что файл действительно лежит в `models/loras/`. Обнови страницу студии **F5** (обычно перезапуск Flask не нужен: список LoRA перечитывается при загрузке страницы). Если файл не виден, см. диагностику ниже.
2. Выбери графическую модель, с которой совместима конкретная LoRA: **SDXL Base 1.0** либо **Illustrious XL v2.0**.
3. В поле **«SDXL LoRA»** вместо **«Без LoRA»** выбери имя `.safetensors`.
4. В промпте опиши картинку и при необходимости добавь **trigger words** из карточки LoRA. Для художественной стилизации с SDXL это может быть, например, «pixel art», но точный триггер зависит от обученного адаптера.
5. Для первого сравнения выставь **1 вариант**, **768 × 960**, **28 Steps**, **CFG 6,5**. Можно использовать фиксированный seed (например, `12345`) и одинаковый промпт для последовательных тестов **без LoRA / с LoRA**, чтобы видеть разницу. Это не обеспечивает идеально идентичные картинки, но помогает сравнивать.
6. Нажми **«Генерировать»**, проверь результат, при ошибке смотри `data/jobs/<job-id>/worker.log`.

**Важные ограничения текущего кода:** выбирается **одна LoRA на одно задание**; сила адаптера зафиксирована на **0,7** (`lora_scale` в spec), отдельного ползунка в веб-интерфейсе нет. Если автор рекомендует другой коэффициент, интерфейс пока не позволяет его выставить. LoRA сама по себе ничего не «дообучает» во время рисования.

## 3. Если нужен образец (img2img): и с LoRA, и без неё

1. В правой панели выбери режим **«По образцу»**.
2. В поле **«Изображение-образец для img2img»** нажми **«Выберите файл»**, выбери PNG/JPEG/WEBP (до **12 МБ**) и **«Добавить»**.
3. Убедись, что загруженное изображение выбрано в списке референсов (просто выбор файла без нажатия «Добавить» недостаточен).
4. **«Сила img2img»**: стартовое **0,55**. Меньшее значение обычно сильнее сохраняет исходный кадр; большее позволяет свободнее изменять его.
5. Выбери **«Без LoRA»** или **подходящую LoRA**. Эти механизмы независимы: img2img использует изображение как исходную точку; LoRA меняет работу весов модели.
6. Вставь описание, установи 1 вариант и нажми **«Генерировать»**.

В текущей реализации одновременно загружается **только один референс**; это **не обучение LoRA**.

## 4. Проекты и граф вместо быстрого рисунка

Режим **«◈ Проекты и граф»** используется для длительной работы со сценами и персонажами. Выбери/создай проект → создай/выбери узел → заполни позитивный/негативный промпты → **«Сохранить узел»**, затем **утверди** узел → справа выбери checkpoint, опциональную LoRA и параметры → **«Генерировать»**.

Для быстрого рисунка граф не нужен. LoRA выбирается в **общей правой панели**, независимо от режима. Шаблон **Karate Linux** — только один из возможных проектов; приложение универсальное.

## 5. Проверка и частые проблемы

| Симптом | Что проверить |
|---|---|
| **В списке только «Без LoRA»** | Файл `.safetensors` в `models/loras/`, а не `lorasas/`; имя и права чтения; F5 |
| **SDXL «установлена», но генерация не стартует** | GPU-окружение, `/api/status`, ошибка задачи и `worker.log`; наличие checkpoint не подтверждает успешный inference |
| **LoRA найдена, но ошибка при загрузке** | Совместимость SDXL/Illustrious, целостность и формат файла, лог GPU worker; `.safetensors` расширение не гарантирует валидность |
| **Эффект слабый/не тот** | Правильный checkpoint, trigger words, особенности обучения адаптера; сила LoRA сейчас фиксирована 0,7 |
| **Режим img2img требует образец** | Сначала **«Добавить»**, затем выбрать загруженное изображение в списке |
| **После F5 слетели параметры** | Обновить код до изменения сохранения настроек; сохранение в браузере зависит от того же origin/профиля и не переживает очистку localStorage |
| **Нет картинки после закрытия вкладки** | Открыть **«История генераций»**, проверить `data/jobs/<job-id>/state.json` и лог задачи |

Полезная локальная диагностика (с **Huananzhi**):

```bash
cd /1tbdisk/PegineLab/ai_draftsman
ls -lh models/loras/
curl -s http://127.0.0.1:9898/api/loras
curl -s http://127.0.0.1:9898/api/status
```

Первый API возвращает список обнаруженных имён LoRA, второй — состояние студии и GPU. Нет ответа на 9898 — проверь, запущена ли панель через `bash scripts/run.sh`. Не выставляй открытый порт 9898 в интернет: в текущей версии нет авторизации.

## 6. Где обучение LoRA?

**Обучение LoRA в AI Draftsman пока не реализовано.** Студия умеет **загружать готовые локальные адаптеры и использовать их в генерации**. Для обучения своей LoRA нужен внешний совместимый SDXL-тренер и подготовленный датасет; на RTX 3060 12 ГБ возможны режимы с экономией VRAM, но работоспособность конкретной конфигурации надо проверять. После обучения полученный `.safetensors` кладётся в `models/loras/`.

См. также [«Откуда берём модель, обучение и память»](TRAINING_AND_MEMORY.md) и [основную документацию](../README.md).
