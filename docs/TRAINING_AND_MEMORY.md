# Откуда берём модель, обучение и память AI Draftsman

## Готовая графическая модель — это уже обученные веса

Illustrious XL v2.0 — готовая SDXL-совместимая модель для иллюстраций. Не требуется скачивать «голую нейросеть» и обучение отдельно: checkpoint уже содержит обученные веса. Официальный источник:

https://huggingface.co/OnomaAIResearch/Illustrious-XL-v2.0

Файл `Illustrious-XL-v2.0.safetensors` (≈7 ГБ) скачивается в `models/checkpoints/` только по явному нажатию. Условия лицензии CreativeML OpenRAIL-M проверить до коммерческого распространения. Один checkpoint не гарантирует точного повторения персонажей между разными сценами.

## Собственная LoRA и обучающие примеры

Персонажей и стиль лучше закреплять отдельными LoRA, обученными на авторских иллюстрациях, которые пользователь имеет право использовать. Порядок:
1. Собрать несколько десятков **качественных, разнообразных, согласованных** изображений одного персонажа с разных ракурсов, выражений, поз и костюмов. Устранить ошибки анатомии и противоположные варианты лица.
2. Добавить текстовые подписи/теги к примерам: отличительные признаки и постоянный специальный токен персонажа (если используется выбранным тренером).
3. Разделить на обучение и контрольные референсы; проверить, что отдельные тестовые изображения узнаваемы и не становятся копией одной картинки.
4. Для SDXL использовать совместимый DreamBooth LoRA тренер. Официальные инструкции: https://huggingface.co/docs/diffusers/main/training/dreambooth и скрипт https://github.com/huggingface/diffusers/blob/main/examples/dreambooth/train_dreambooth_lora_sdxl.py .
5. RTX 3060 12 ГБ требует экономного режима и настройки памяти. Обучение **не внедрено в текущий AI Draftsman**; пока приложению можно дать уже полученную совместимую LoRA в `models/loras/`.
6. Для внешних LoRA проверять базовую модель (SDXL, не Flux и не SD 1.5), лицензию и условия использования. Загрузка случайного файла `.safetensors` не гарантирует совместимость.

## Работа по одному и нескольким образцам

В настоящий момент приложение реализует только img2img по **одному** референсу. Это генерация на основе входной картинки, а не обучение и не поиск по базе референсов. Для одновременного использования образца персонажа, фона и стиля отдельно нужны дополнительные адаптеры, например IP-Adapter с совместимым графическим pipeline: https://huggingface.co/docs/diffusers/main/using-diffusers/ip_adapter . Они пока не установлены и не заявлены готовыми.

## Что реально запоминается после обновления страницы

| Данные | Где хранится | После F5 |
|---|---|---|
| Список проектов, промпты проекта, выбранная LLM | SQLite `data/draftsman.db` | Да, после нажатия «Сохранить проект» |
| Узлы, связи, координаты, подписи, статусы | SQLite `studio_nodes` и `studio_edges` | Да, после явного сохранения, drag сохраняет координаты |
| Контекст проекта TXT/MD | SQLite FTS5 `studio_knowledge` | Да |
| Быстрый положительный и негативный промпт | SQLite `quick_draft` | Да, после «Сохранить черновик» или «Генерировать» |
| Параметры запуска, job ID и лог | `data/jobs/<id>/spec.json`, `state.json`, `worker.log` | Да |
| Полученные master PNG и PNG-8 | `data/jobs/<id>/images/` | Да |
| Содержимое GPU VRAM | Только в процессе генерации | Нет; процесс завершается |
| Временная память чата Ollama | По её настройкам; `keep_alive=0s` выгружает модель | Нет; для постоянства используется SQLite и RAG |

**Важная граница:** графовая память сохраняет данные для сценариста Qwen и для формирования положительного/негативного промпта. Сама Illustrious XL не «читает SQLite» и не приобретает новые знания от одной генерации. Постоянство облика задают референсы, LoRA и контролируемые промпты.

## Ожидание и мониторинг

- Карточки-скелетоны показывают число заказанных вариантов; этап и процент берутся из файла `state.json`, который обновляет GPU worker.
- Браузер запрашивает статус раз в 4 секунды **только во время активного задания**, пропускает запросы, пока вкладка скрыта, и останавливается после результата или ошибки.
- Текущий мониторинг CPU/RAM/VRAM/SWAP/дисков/зомби запрашивается **только вручную**. Он не пишет историю телеметрии и не нагружает браузер фоновыми графиками.
- Python GPU worker завершается после задания, освобождая свою видеопамять. Ollama — отдельный сервис.

## Статус реализации

Код интерфейса и backend есть на GitHub; реальный серверный тест SDXL и художественное качество ещё нужно подтвердить отдельно. Обучение LoRA, multi-reference, векторный индекс изображений, качественный анализ кадра, автоматические издательские ZIP — следующие этапы, не обещанные как готовые.
